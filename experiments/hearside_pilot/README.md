# 听侧适配小实验（hear-side pilot）

**状态（2026-11-23）：已在服务器上完整运行一次，每臂一个种子。按预先声明的判据，结论是 `stop`，见“结果”一节。后续实验（层数与种子）已运行，四项判读均为 `supported`，见 `results/followup-20261123-212622/NOTES.md`。第三轮（补种子、跨格式评测、余量检验）已声明，尚未运行。**

## 要回答的问题

D2/D2b 诊断在 IEMOCAP Session 4 上得到两件事：

- 冻结基座对音高、能量的改动有反应，但各类别此消彼长，UAR 上相互抵消。
- 普通监督 LoRA（pair-01）在训练时的选项顺序下 UAR 67.7%，且确实依赖韵律；把同样的四个选项换个顺序，UAR 降到 40–45%，低于冻结基座的 52–60%。它学到的一部分是“音频 → 答案字母”的捷径。

由此提出一个可以被否定的假设：**把适配器的更新只加在音频 token 的位置上，让冻结的语言模型自己读题、作答，可以学会用声学信息而不绑定答题格式。** 小实验同时检验一个更便宜的解释：训练时打乱选项顺序就够了，位置限制没有独立作用。

这不是新结构的主张。位置受限的低秩更新本身很简单，相关工作的核查尚未完成（见“局限”）。小实验只决定这个方向值不值得继续。

## 四个臂

| 臂 | 更新加在哪些位置 | 训练时的选项顺序 | 作用 |
|---|---|---|---|
| `A-all` | 全部位置 | 固定 | 普通低秩适配，参照 |
| `B-audio` | 只在音频 token 位置 | 固定 | 待检验的做法 |
| `C-post-audio` | 只在最后一个音频 token 之后（问题、答案） | 固定 | 机制对照：只改“答”的一侧 |
| `D-all-shuffled` | 全部位置 | 四种循环顺序，类内均衡 | 便宜的替代解释 |

四个臂只在表中两列上不同，其余完全相同：

- Thinker 全部 36 层的注意力 O 投影，r=8、alpha=16，`gate_multiplier=0`（没有传输项，就是 B·A·x）。每臂 1,179,936 个可训练参数，其中每层 8 个 gate 参数不起作用。
- 用 36 层而不是 pair-01 的最后 4 层，是因为最后一层在音频位置上的更新到不了答案位置（单元测试 `test_audio_updates_in_the_last_layer_cannot_reach_a_text_answer`），听侧更新必须落在更早的层。
- 训练配方取自服务器上的 `pair-01/config.json`（学习率 2e-4 常数、batch 2 × 累积 4、1 个 epoch、seed 42），只把评估间隔改为 88 步。
- **Sessions 1–2 训练（2108 句左右，264 步），Session 3 选 checkpoint（第 88、176、264 步三次），Session 4 只评测，Session 5 不读取。** `data.py` 发现源清单含 Session 4/5 会直接报错。pair-01 当时用 Session 4 选 checkpoint，这里不再这样做。
- `D` 的训练集和选模集与其他臂是同一批语句、同一顺序，只是每句的选项被循环移位（`data.py`）。选模用的是训练器现有的指标，按答案字母计 UAR；对 `D` 来说字母与类别不再一一对应，这个数只用来挑 checkpoint，不与其他臂的 Session 3 成绩比较。

位置限制在 `experiments/ms_swift_librispeech/swift_asr_ta_runtime.py` 里实现（`update_positions`，checkpoint 格式 10）。不设这个选项时，原有格式 1–9 的读写和前向不变。

同一次提交里还有一处与位置无关的改动：乘子为 0 且没有独立 C 矩阵时，传输项恒为零，runtime 不再计算它的注意力对比项。输出与 A、B 的梯度逐位不变（`test_zero_multiplier_skips_the_contrast_without_changing_outputs_or_gradients`），省掉每层两张 FP32 注意力图及其反向缓存；gate 参数此时没有梯度（原先是零梯度）。四个臂都走这条路径。

## 评测

`pilot-iemocap-session4.json`，沿用 D2b 的语句、问题和四种选项顺序（1026 句 × 4 = 4104 行），按类别计分。

| 输入 | 内容 |
|---|---|
| `orig` | 原始录音，训练时的问法 |
| `orig_reworded` | 原始录音，另一种问法和版式（所有臂都没见过） |
| `text` / `question_only` | 只给转写 / 只给问题 |
| `asr-orig` | 300 句子集的转写，WER 在去掉“The transcript is:”这类引导语后计算 |

“训练顺序”指 A=angry、B=happy、C=sad、D=neutral 这一种，“其他顺序”指另外三种循环移位。区间是按对话聚类的 95% bootstrap（10000 次，seed 42）。

`B-audio` 对不含音频的输入不做任何更新，所以它在 `text` 和 `question_only` 上与冻结基座逐位相同。这是构造决定的，不是实验发现。

## 预先声明的判据

写在 `summarize.py` 的 `CRITERIA` 和 `decide` 里，训练前固定。

| 检查 | 对比 | 通过条件 |
|---|---|---|
| 听侧学得会 | `B − A`，`orig`，训练顺序 | UAR 差 ≥ −3 pp |
| 听侧没有丢掉读题能力 | `B − 冻结基座`，`orig`，其他顺序 | UAR 差 ≥ 0 |
| 听侧不绑定格式 | `B − A`，`orig`，其他顺序 | UAR 差 ≥ +10 pp |
| 打乱选项不能替代 | `B − D` | 改写问法（全部顺序）UAR 差的区间下界 > 0，**或** WER 差的区间上界 < 0 |

四项全过记为 `continue`，任何一项不过记为 `stop`，缺臂记为 `undecided`。

读结果时的三种情形：

1. 前三项通过、第四项不过：打乱选项就能得到同样的效果，位置限制没有独立价值，这条线停止。
2. 四项全过：位置限制本身就有用。能写的是“简单做法 + 诊断”，不是新结构。
3. 第一项或第二项不过：只改音频位置学不会，或者学会了却损害读题。这时才有理由讨论额外的组件，也可能说明假设本身不成立。

`C-post-audio` 不进判据。它用来看格式绑定是否来自“答”的一侧：如果 C 与 A 一样绑定格式而 B 不绑定，机制解释才站得住。

## 结果（2026-11-23，每臂一个种子）

服务器运行一次，201 分钟，记录在 `results/20261123-160928/`（汇总、配置、日志和各条件的聚合指标；不含逐题预测、转写和音频）。Session 4，1026 句 × 4 种选项顺序，UAR %：

| 臂 | 录音，训练顺序 | 录音，其他顺序 | 改写问法，全部顺序 | 只给转写 | WER % |
|---|---:|---:|---:|---:|---:|
| 冻结基座 | 52.1 | 57.4 | 59.0 | 48.3 | 9.0 |
| `A-all` | 76.2 | 72.7 | 74.5 | 49.8 | 7.9 |
| `B-audio` | 75.4 | 74.4 | 75.6 | 48.3 | 8.8 |
| `C-post-audio` | 72.7 | 66.1 | 66.2 | 48.6 | 8.8 |
| `D-all-shuffled` | 77.4 | 75.6 | 76.4 | 50.0 | 7.3 |

| 检查 | 实际值 | 结果 |
|---|---|---|
| 听侧学得会（`B − A`，训练顺序 ≥ −3 pp） | −0.78 [−2.89, +0.99] | 通过 |
| 听侧没有丢掉读题能力（`B − 基座`，其他顺序 ≥ 0） | +16.93 [+13.91, +20.29] | 通过 |
| 听侧不绑定格式（`B − A`，其他顺序 ≥ +10 pp） | +1.68 [+0.55, +2.87] | **不通过** |
| 打乱选项不能替代（`B − D`） | 改写问法 −0.80 [−1.92, +0.51]；WER +1.45 [+0.44, +2.71] | **不通过** |

**按预先声明的规则，结论是 `stop`。**

- 第三项不通过的原因不在 B，而在 A：36 层的普通低秩适配在换选项顺序后只掉 3.5 pp，并没有出现 pair-01（最后 4 层）那种掉到基座以下的格式绑定。这个小实验要解决的问题，在它自己的参照臂上基本不存在。上面“三种情形”没有列出这种情况。
- 打乱选项（D）在准确率上不低于 B，成本更低。位置限制不能作为一个更好的方法来主张。
- B 与 A 的准确率相当，说明这项任务上的增益只靠改音频位置就能拿到；只改音频之后的位置（C）增益更小，也更依赖选项顺序。这些是事后观察，见 `results/20261123-160928/supplementary.md`，需要更多种子和同一流程下的层数对照才能下结论。

### 预先声明的判读

写在 `followup.py` 的 `CRITERIA` 和 `judge` 里。“顺序差”指训练顺序的 UAR 减去其他三种顺序的 UAR。

| 说法 | 量 | `supported` 的条件 |
|---|---|---|
| `last_layers_bind_to_option_order` | `A-last4` 的顺序差 − `A-all`（seed 42）的顺序差 | ≥ 10 pp，且对话 bootstrap 的区间下界 > 0；否则 `not supported` |
| `audio_positions_match_all_positions` | 三个种子平均的 `B − A`，四种顺序合计的 UAR | 区间完全落在 ±3 pp 之内；完全落在之外为 `contradicted`，其余 `inconclusive` |
| `audio_positions_less_bound_to_option_order` | 三个种子平均的 `B` 的顺序差 − `A` 的顺序差 | 区间上界 < 0；下界 > 0 为 `contradicted`，其余 `inconclusive` |
| `shuffled_options_improve_all_positions` | 三个种子平均的 `D − A`，四种顺序合计的 UAR | 区间下界 > 0；上界 < 0 为 `contradicted`，其余 `inconclusive` |

三个种子的平均值，其区间同时重采样种子和对话（比较的两个臂共用同一组种子抽样）。三个种子的重采样很粗，汇总里同时列出每个种子的数值、均值和标准差。某个种子的臂训练失败时，用各臂共有的种子计算，少于两个则不判读。

各结果的含义也在这里先写下：

- 层数一项 `supported`：可以在同一流程内说“只改最后几层的适配更依赖选项顺序”，仍限于单种子、单语料。`not supported`：pair-01 的格式绑定来自别的差异（训练数据、步数、用 Session 4 选模、实现），不能归因于层数，需要逐项复现 pair-01 的条件。
- 种子三项若为 `inconclusive`：不能说 A、B、D 之间有差别，能报告的只有 `C-post-audio` 明显更差这一条单种子结果。

### 2. 跨格式评测（`formats.py`）

问题：在四选一字母题上训练得到的增益，换一种问法还剩多少。这是为“找方法缺口”做的：只有当简单做法（36 层 LoRA + 打乱选项，即 `D-all-shuffled`）在某种问法上明显不行，才有理由设计新方法。

三种所有臂都没见过的问法，同样的 Session 4 录音，自由生成（贪心，最多 16 个 token）：

| 格式 | 问法 | 行数 | 计分 |
|---|---|---:|---|
| `yesno` | “Does the speaker sound <情感>? Answer yes or no.” 每句问两次：真实情感、一个错误情感 | 2052 | yes、no 两类召回率的平均 |
| `word` | 四个情感以词给出（两种顺序），要求用词回答 | 2052 | 四类 UAR |
| `open` | 不给选项，用一两个词描述 | 1026 | 四类 UAR |

解析规则和词表写在 `formats.py`（`parse_yesno`、`LEXICON`）：是非题取第一个词；情感词按整词匹配，恰好命中一类才算有效，无法解析的回答记为错。词表里 frustrated 归入 angry，这是事先定下的近似（IEMOCAP 的 frustrated 是另一类，四分类里没有它）。

预先声明的判读，对每种格式看 `D-all-shuffled`（三个种子平均）减冻结基座：

| 判读 | 条件 |
|---|---|
| `base at ceiling` | 冻结基座在该格式上 ≥ 85%，没有可比的余地 |
| `harmed` | 增益的区间上界 < 0 |
| `gap` | 增益小于它在训练问法上增益的一半（训练问法上约 +17.4 pp，即门槛约 8.7 pp） |
| `transfers` | 其余情况 |

出现 `gap` 或 `harmed` 才算找到了一个值得为之设计方法的场景，而且还需要在第二个语料上复现。三种格式都是 `transfers`，就说明普通做法已经把“听”的能力带到了别的问法上，这条找缺口的路没有结果。汇总里同时列出 A、B、`A-last4`、C 各自相对基座的增益，以及 B − A、D − A、`A-last4` − `A-all`，这些只作描述，不设判据。

### 3. 输入条件化的余量检验（`headroom.py`）

判据见 `research/headroom-test-input-conditional-20261124.md`，这里不重复。实现上的细节：

- 共用适配器是 `D-all-shuffled`，专用适配器沿用它的配置，只把评估间隔改成各自总步数的三分之一。
- 时长按训练集的三分位点分三档；随机对照 `random2` 的两份与性别两组等大，`random3` 的三份与时长三组等大。即兴/剧本两组不等大，用 `random2` 近似。
- 专用适配器只训练了 seed 42，与共用适配器的 seed 42 配对比较。
- 种子标准差取自后续实验：4.06 pp，所以“超过两倍标准差”这一条的门槛约为 8.1 pp。按这个门槛，很可能三种分组都不通过。

## 运行

服务器上一条命令（克隆 `main` 的当前版本并在后台运行）：

```bash
R=/root/autodl-fs/CoTA-LoRA; S=$R/src-$(date +%Y%m%d-%H%M%S)
git clone --depth 1 https://github.com/shanmon110/CoTA-LoRA.git "$S" && cd "$S" \
  && nohup bash experiments/hearside_pilot/run_pilot.sh > "$R/hearside-pilot.out" 2>&1 &
```

`run_pilot.sh` 依次做：环境检查 → 单元测试（不通过就停，不训练）→ 生成清单和配置 → 评测冻结基座 → 每个臂训练后立刻评测 → 汇总 → 打包。所有输出在 `$R/hearside-pilot-<时间>/`，结束时（包括中途失败）生成 `$R/hearside-pilot-<时间>-for-claude.tar.gz`，只含日志、清单、预测和汇总，不含权重和音频。

后续实验把上面命令里的 `run_pilot.sh` 换成 `run_followup.sh`（输出目录 `hearside-followup-<时间>`），七个臂预计约 5 小时，依据是小实验的实测：每臂训练加选模约 16 分钟、评测 25–28 分钟。

第三轮用 `run_next.sh`（输出目录 `hearside-next-<时间>`），估计 8–10 小时：补种子约 1.5 小时；跨格式评测 14 个模型，每个约 5100 次短生成，速度没有实测，按 3–5 小时估；余量检验 12 次小训练加评测约 3 小时。`STAGES="2"` 之类可以只跑其中一部分。

看进度：`tail -f /root/autodl-fs/CoTA-LoRA/hearside-pilot.out`。中断后续跑：`RUN=<同一个输出目录> bash experiments/hearside_pilot/run_pilot.sh`，已完成的步骤不会重做，被打断的训练目录改名保留后重新训练。

2026-11-23 的实测：全程 201 分钟。每臂训练 400–455 秒，训练中三次 Session 3 评估另需 515–564 秒，训练峰值显存 22.3 GB（已分配）；每个模型的 Session 4 评测 25–28 分钟。

- 只有一种改写问法、一个任务、264 步训练。
- 相关工作核查未完成。此前检索到、但尚未精读的方向包括：只在语音位置加 LoRA 的做法、音频语言模型的选项顺序偏置、微调造成的格式特化。在核查完成之前，不对新颖性作任何表述。
