# Methods 11–20 on the Qwen2.5-Omni Thinker

The common pilot supplies the base snapshot, target decoder projections, source audio, validation, optimizer and evaluation. Entries below identify the method-specific behavior, including deliberate experiment choices. The method recipes live in `papers28/configs/`. Shared projection methods accumulate their adapter residual in FP32 and return the base output dtype.

## Direct checks against the authors’ code

`python -m experiments.ms_swift_aqa.paper_middle_author_parity --sources <author-checkouts>` runs the pinned AuroRA, GraLoRA, Magnitude-LoRAM and TopLoRA files from four sibling directories named `aurora`, `gralora`, `magnitude-loram` and `toplora`. The runner checks each source file SHA256 before loading it. On a rectangular FP32 layer with nonzero adapter weights, output and input-gradient maximum absolute differences were zero for all four. The Magnitude-LoRAM check also compares both starting factors and the compensated base weight. The pilot log is `logs/middle-author-upstream-parity.log`. The independent BF16 Swift audio-update and exact clean-reload tests for seven plug-ins are recorded in `logs/middle-swift-omni-audio.log`.

## Rebuilding LowRA

The source snapshot manifest identifies every original model shard. The preprocessor checks the official shard checksums used by all 252 decoder projections. The packed bundle's index pins every resulting shard by SHA256. A checkpoint pins the bundle index. Set `SWIFT_LOWRA_BASE` to relocate an identical copy.

```bash
CUDA_VISIBLE_DEVICES="" OMP_NUM_THREADS=6 MKL_NUM_THREADS=6 NUMBA_NUM_THREADS=6 OPENBLAS_NUM_THREADS=2 \
python -m experiments.ms_swift_aqa.paper_middle_lowra \
  --model /root/autodl-tmp/west-preflight/model \
  --snapshot experiments/ms_swift_librispeech/evidence/verified_snapshot.json \
  --output /root/autodl-tmp/MMAR/runs/papers28-transfer-01/lowra-base \
  --bpp 1.75 --rank 8 --alpha 16
```

This run stored 4,855,431,168 payload bits for 2,774,532,096 decoder weights. The packed files also store row offsets, per-channel tables, block scales and the initial FP32 adapter matrices. Including those fields, the shard files total 911,554,704 bytes. The index digest is `0e0d2c87e4b54f1f87caa2af6717f9459f396ba1fb8a0039ead08786ad9c3ed4`. The rest of the Omni model and runtime activations add to device memory. Training and evaluation load one dense projection temporarily for its matrix multiply. Backward reconstructs each frozen weight as needed.

Each CUDA process validates the active Triton kernel once per device before using packed weights. The check compares exact FP32 and BF16 reconstruction, forward matmul and input gradients against dense PyTorch, using a mixed-bit fixture with a partial final tile. Training records the result, CUDA device, library versions and kernel source hash in `adapter_config.json`. Evaluation and retries repeat the same check on their active device.
