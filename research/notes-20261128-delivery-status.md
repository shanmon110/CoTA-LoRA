## 2b. 源码级复核的结果（本次新增，零成本）

`research/notes-20261128-source-review.md`，工具 `research/tools/checkpoint_audit.py`。

**本文所有臂的 `gate_multiplier` 都是 0.0，传输项是可证明的恒等 no-op。**
所以本文测的是**「r=8 低秩更新放在哪些层」**，**不是**「CoTA 传输机制放在哪些层」。
这是有意的、仓库 README 和单元测试都写明的设计，**不改变任何结果**，
但**改变臂的命名**——论文的表必须写成 "low-rank update, last 4 layers"，
不能写成 "CoTA last 4 layers"，否则是误述方法。

**这是三条独立证据，不是一条：**

1. **读源码**：`gate_multiplier == 0` 让传输项**逐位**成为恒等 no-op
   （`swift_asr_ta_runtime.py:470`）。
2. **数值复现**：multiplier 0 时 `grad(gate) is None`；multiplier 1 时 `grad(gate)` 非零。
3. **来自训练本身**（**最强的一条**）：每个 checkpoint 都存了训练循环自己写的
   `optimizer.pt`。Adam **只为它真正更新过的参数分配状态**。
   **全部 44 个臂、全部 144 个门参数：0 个有优化器状态；
   而 100% 的 `down`/`up` 因子都有**（数百步之后仍非零）。
   **所以门项在每一个臂里都从未被更新过**——不是"学得小"，是"没有被步进过"。
   工具：`research/tools/gate_optimizer_state.py`。

另外核对了：首答案查询在这些臂里**没有启用**（`transport_gate` 全为 `None`）；
模态划分是**构造性的**（由 audio token id 决定，没有可调超参）；
cache 只支持 append-only `DynamicCache`；
**Omni 路径显式拒绝梯度检查点**（与交接文档一致，已在本仓库核实）。

**测量到的位移（第三个新结果）**：用 `initialization.json` 里的种子
在隔离的 CPU RNG 上重建初始 A，再逐字节核对记录的 SHA——**全部 30 个臂的重建 SHA 精确匹配**。
在**相对**位移上，**4 层臂移动得比 36 层臂远 2–3 倍**（0.30–0.72 对 0.18–0.33）。
**这是层段比较从未分离掉的混杂。** 但它**不解释方向**：
移动最远的臂（`AQ-first4`，0.718）是最差的。工具：`research/tools/adapter_displacement.py`。

## 7. **本轮结论的诚实汇总**（2026-11-28 收尾）

### 7.1. **本文的贡献是分析论文，不是方法论文** —— 而且现在有了硬证据

三条互相独立的证据说明**本文测的不是 CoTA 的传输机制**：

| 证据 | 内容 |
|---|---|
| 读源码 | `gate_multiplier == 0` ⇒ 传输对比项不进前向（`swift_asr_ta_runtime.py:470`） |
| 数值复现 | multiplier 0 时 `grad(gate) is None`；multiplier 1 时非零 |
| **训练本身** | **全部 44 个臂、144 个门参数，0 个有优化器状态**；`down`/`up` 100% 有 |

再叠加审计结论：**历史臂每层只存 `down`/`up`/`gate`，独立 C 压根不存在**，
**所以历史臂在数学上与普通 r=8 LoRA 完全等价**。

**这不是缺陷**——本文要测的是"低秩更新放在哪一层"，这正是普通 LoRA 的问题。
**但正文必须写清楚**，否则会被读成在测一个它并没有测的方法。

| CREMA-D | 同句不同韵律 | 逐情感边缘被重写：`A-all` SAD **+34.5**、HAP **+15.3**、ANG **+16.5** |
| AVQA（留出） | MCQ 准确率 | 同分布 **+7.27 pp**，四个选项序**都涨**（+5.9 到 +7.9），顺序差几乎不变 |
| MMAU | MCQ 准确率 | 跨语料 **−2.81 pp**，负迁移落在**需要音频**的题上 |

**统一的说法：适配器重写了输出边缘。**
**在源分布上重写得更准（所以涨），跨语料时重写得不适用（所以跌）。**

**而且"压平"这个说法被两次修订掉了，必须写清楚：**
1. AVQA 的音频题上是**相反**的方向——适配器把基座的平边缘**变陡**，而且变陡的那个**是对的**；
2. CREMA-D 上 `A-last4` 不是均匀压平，而是**朝中间挪**（HAP +8.1、NEU −6.6、SAD −4.5）；
   按"离均匀边缘的距离"算，`A-all` 反而比基座**更陡**（38.2 对 32.7 pp）。

**所以论文里能写的只有一句：适配器重写了逐类的输出边缘，
移动方向取决于语料和层段，而在源分布上移动的方向是对的。**

**这条线顺手解释了本项目最反直觉的一条观察：**
**为什么"适配器的效果"在两个任务上相反、层段排序也是相反的。**
**因为这是同一个量的两面：学会了多少，以及有多少迁移不掉。**
`AQ-all` 学到很多（+7.27）也迁移不掉很多（−2.81）；`AQ-last4` 两边都很少（+0.08 / −0.56）。
**所以层段该按"学会了多少、迁移不掉多少"来选，
而不是按"迁移后掉多少"来选——后者会把"学得少"误判成"更稳健"。**
