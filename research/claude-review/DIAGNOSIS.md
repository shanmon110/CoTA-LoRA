## 0. 最可能改变研究结论的五件事

1. **"条件门"至今没有被真正检验过。** 在现有学习率和步数下，动态门矩阵 `R` 和静态门 `g` 在数值上几乎不起作用：`R` 的幅度与"梯度纯噪声时 Adam 的随机游走"吻合，训练时它引起的乘数变化大部分被 BF16 舍入抹掉。static / question / question_audio 三个臂实际上是同一个模型加噪声。（§1.1）
2. **选模指标的噪声比各臂差距大一个量级。** 配对指标在被选中的第 160 步仍在快速上升，8 次更新之后又变化最多 19 个百分点（中位数 13.5）；9 个臂里 8 个都选了最后一个常规评估点，等于没有选模。（§1.2）
3. **目标集测到的主要是负迁移，分辨不出 CoTA 与 LoRA。** MMAU 上微调比冻结基座低 3.2 pp（显著），CoTA 与匹配 LoRA 只差 4 道题（12 对 16，p = 0.57）。28 篇表里 MMAU 高的方法，恰好是没学会源任务的方法。（§1.3、§2.3）
4. **传输分支唯一的正面证据很薄。** "开关差 +8.33 pp"只出现在 4 个检查点中的 1 个、且只在它自己训练分布的合成配对上；真实开发集、MMAR、MMAU 上开关差为 0 或负。（§1.3）
5. **多个论文基线的低分来自共用的学习率设置或初始化数值问题，不是方法本身。**（§1.6）

对"为什么 CoTA 没有稳定超过 LoRA"的直接回答：**在现有实验里，CoTA 相对 LoRA 真正多出来的只有"在首答案位置加一个 rank-8 的音频/文本差读出 `C`"，同时普通分支的秩从 12 降到 8；而评测既没有足够的分辨力看出这点差别，也没有针对"是否用上了音频"来设计。** 现有数据既不能说明 CoTA 有效，也不能说明它无效。

## 1. 已由代码或仓库内证据确认

### 1.1 动态门 `R` 与静态门 `g` 在现有预算下数值上不起作用

涉及代码：`experiments/ms_swift_librispeech/swift_asr_ta_runtime.py`

- L27–28、L92、L166：`B`、`g`、`C`、`R` 全部零初始化；只有 `A` 是 Kaiming（L35）。
- L59–63：`m = 2σ(R·f)`，`f` 是两个单位向量之和除以 √2，所以 `‖f‖ ≤ √2`。
- L65–77 `answer_update`：传输项为 `B(g ⊙ m ⊙ z) + C(m ⊙ z)`。
- L72：`extra = (extra * multiplier).to(extra.dtype)`。

**(a) 门的梯度是 `C` 和 `g` 梯度的"径向分量"，初始为零。** 对任意损失逐样本成立：

`m_k · ∂L/∂m_k = (Cᵀ ∂L/∂C)_kk + g_k · ∂L/∂g_k`

也就是说，门能收到的学习信号，正好是"把 `C` 的第 k 列整体放大或缩小"这个方向上的梯度。这个方向 `C` 自己就能直接走，所以门的"常数部分"与 `C` 完全冗余；`C=0, g=0` 时门的梯度恒为零。仓库自己的测试也断言了这一点（`tests/test_conditional_gate.py` L48）。数值验证见 `checks/numerics.py::redundancy_check`（有限差分误差 2.8e-8）。

**(b) `R` 的实际幅度等于无信号的 Adam 随机游走。** 用已发布的门探针（`research/evidence/derived/ta-conditional-01/gate-probe*.json`，检查点第 160 步）：

| 运行 | 门学习率 | `R` 元素 RMS（实测） | 纯噪声预测 `lr·√T` | 方向一致预测 `lr·T` | 实测/纯噪声 |
|---|---:|---:|---:|---:|---:|
| question_audio | 2e-4 | 0.00227 | 0.00253 | 0.0320 | 0.90 |
| fastgate | 3.2e-3 | 0.0370 | 0.0405 | 0.512 | 0.91 |

对照模拟（同样的 Adam 超参）：梯度信噪比为 0 时该比值是 1.03，信噪比 0.1 时就到 1.61。两次运行的逐层比值平均为 16.5，几乎正好等于学习率之比 16。**结论：`R` 收到的梯度没有稳定方向，它是被 Adam 归一化之后的噪声推着走的。** 把门学习率提高 16 倍只是把同一个随机游走放大 16 倍。

这是由日志推出的强证据，但严格说还不是直接测量（没有逐步梯度记录）。本分支加了 `adapter_stats.py`，下次训练会直接记录 `R` 梯度相邻两次的余弦，可以一步证实或否定。

**(c) 训练时 BF16 把小的乘数舍掉了。** 训练配置 `bf16=True`（`train.py` L325），TA 适配器参数是 FP32（runtime L25；PEFT 臂见 `train.py` L209）。在 autocast 下 L67 的 `F.linear` 输出 BF16 的 `extra`；L72 把 `extra × m` 再转回 BF16。BF16 只有 8 位有效数字，所以：

- `|m − 1| < 2⁻⁹ ≈ 0.00195` 时，每个系数都**精确地**舍回原值，门在前向里完全不存在；
- `|m − 1| > 2⁻⁸ ≈ 0.0039` 时才必然可见。

门探针给出的 `|m − 1|`：均值 0.0017，各域中位数全部低于 2⁻⁹，p95 约 0.0047。按这个分布估算，学习率 2e-4 的运行在训练结束时约 80% 的门控系数在前向里没有任何变化（训练前期更多）；fastgate 约 9%。而反向传播把这个类型转换当作恒等，所以 `R` 仍在更新——优化器在调一个前向基本看不见的参数。

注意两点。第一，推理不走 autocast（`evaluate.py` L124 直接调 `generate`），系数是 FP32，门在推理时是"生效"的，这造成训练与推理的数值路径不一致。第二，"训练前向确实在 autocast 下"是根据 transformers 4.52.3 + accelerate 的行为推断的（`bf16=True` 时 accelerate 包装 `forward`），仓库里没有直接证据，需要在服务器上用一行断言确认（见 [`PROTOCOL.md`](PROTOCOL.md) 的 P0）。

**(d) 静态门 `g` 同样到不了有意义的幅度。** `g` 从 0 出发、学习率 2e-4、168 步，Adam 每步位移约为 lr，所以 `|g| ≲ 0.034`。若 `B` 与 `C` 量级相当，共享读出 `B(g ⊙ z)` 的贡献不到 `C z` 的 4%。（这是上界推导；仓库没有发布 `g` 的数值。）

**(e) 门的"样本相关部分"只占它自身偏离的一成。** 同一探针里，固定题干换音频时 `m` 的平均变化是 1.87e-4，而 `|m − 1|` 的均值是 1.7e-3；fastgate 是 2.9e-3 对 2.9e-2。两次都约为 10%：门学到的九成是一个与输入无关的常数偏置。

**后果。** 
- static（66/96）、question（70）、question_audio（71）、fastgate（68）这四个同种子臂的差别不能归因于门控，它们给出的其实是这个指标的噪声下限：约 5/96 ≈ 5 pp。
- 现在的 CoTA 等价于"rank-8 LoRA + 首答案位置的 rank-8 读出 `C`"。"条件""动态"在已有实验中没有对应的可测行为。
- 论文若保留 Conditional 这个词，必须先让门在数值上成立，再用同位置静态对照证明它有用。

### 1.2 选模指标不能支撑现有的比较

来源：`research/evidence/raw/ta-conditional-01/train/*/logging.jsonl`（`checks/numerics.py::selection_summary` 重算）。

| 臂 | 96 对中两条都对（第 32→168 步） | 160→168 的变化 |
|---|---|---:|
| lora（短） | 7, 19, 46, 64, **75**, 62 | −13.5 pp |
| static | 6, 17, 46, 56, **66**, 53 | −13.5 pp |
| question | 7, 18, 39, 56, **70**, 53 | −17.7 pp |
| question_audio | 6, 20, 41, 51, **71**, 53 | −18.8 pp |
| fastgate | 7, 19, 43, 57, **68**, 54 | −14.6 pp |
| lora-mixed | 16, 32, 48, 63, **68**, 64 | −4.2 pp |
| question_audio-mixed | 13, 27, 45, 57, **68**, 64 | −4.2 pp |

- 所有臂在第 128→160 步之间仍在上升，训练在指标上升途中结束（1 轮 168 步，恒定学习率 2e-4，无预热无衰减）。这不是早停选出的最优点，而是"截断处的最大值"。
- 8 次更新就能让指标变化最多 19 pp（9 个臂的中位数 13.5 pp），而各臂之间的差距是 0–5 pp。96 对的二项标准误本身就有 4.7 pp。
- 第 160→168 步的下跌在所有短版臂中同时出现，说明它由共同的数据顺序驱动，而不是方法差异。
- 这个指标是合成的"突发声计数 / 响度 / 间隔"任务（`experiments/ms_swift_aqa/prepare_pairs.py` L23–50），冻结基座只有 4–5/96。用它给 MMAU、MMAR、IEMOCAP 这些语义任务选检查点，两者之间没有已建立的关系。

|---|---:|---:|---|

### 1.4 首答案位置、mask、cache、泄漏、关闭语义：静态检查未发现错误

逐项核对了 `swift_asr_ta_runtime.py`：

| 检查项 | 位置 | 结论 |
|---|---|---|
| 训练时查询位置 = 首个监督 token 的前一位 | L186–190 | 正确；并校验该位置是有效文本 token（L191） |
| 推理时查询位置 = 最后一个有效 prompt token | L182 | 正确；评测强制左填充（`evaluate.py` L121–122），两种填充方向下该式都成立 |
| 问题表示不含答案 | L195–201 | 只取"最后一个音频 token 之后、查询位置及之前"，无泄漏 |
| 因果与 padding 可见性 | L224–226 | key 限制在 `≤ t*` 且有效，再与注意力 mask 取交 |
| 音频或文本分区为空 | L205–209、L239 | 置零且不产生 NaN 梯度 |
| 生成时后续 cache 步传输为零 | L215–218、L239 | 位置不匹配即不合格；评测只生成 1 个 token |
| beam、外部 cache、packing、视觉输入 | L361–377、L439–443 | 明确拒绝 |
| Omni 梯度检查点 | L425–426 | 明确拒绝，配置为 false |
| 完整关闭传输 | `transfer_eval.py` L19–33 | 同时清零 `g` 和 `C`，语义完整 |

这部分我只做了阅读，没有执行。仓库 `research/validation/conditional-gate-tests.log` 记录了原环境 13 项条件门测试通过，与阅读结论一致。

一个设计层面的观察（不是 bug）：问题表示是 `A · e_prompt`（L70），其中 `e_prompt` 是输入 embedding 的均值，而 `A` 是为"各 head 的 value 拼接空间"训练的下投影。两个空间没有对应关系，`A` 对 embedding 均值的投影在语义上是随机投影。再加上题干之后约有二十多个模板 token 对所有样本完全相同，这个特征在样本间的区分度预计很低（见 §2.1）。

### 1.5 参数预算与缩放核对无误，但预算的用法值得注意

用 `2·r·2048 (+r +r·2048 +r²)` × 36 层重算（`experiments/cota_review/make_configs.py`）：LoRA r12 = 1,769,472；static = 1,769,760；question_audio = 1,772,064，与 `result.json` 一致。两者 `alpha/r` 都是 2，不存在缩放不匹配。

但 CoTA 把三分之一的参数（`C`，589,824 个）用在每条样本的**一个 token 位置**上，换来的代价是普通分支的秩从 12 降到 8。现有对照没有把这两件事分开：没有 rank-8 的普通 LoRA，也没有"同位置、同参数、但输入不是音频/文本差"的对照。

### 1.6 退化基线分两类，都不能作为方法优劣的证据

来源：`research/evidence/raw/papers28-transfer-01/train/*/logging.jsonl`。所有臂共用恒定学习率 2e-4、无预热，覆盖 36 层的 Q/K/V/O + MLP（1497 万参数）。

| 方法 | 首个 batch 的 loss（更新前） | 第 1 步梯度范数 | 之后 | 类别 |
|---|---:|---:|---|---|
| 普通 LoRA | 0.2723 | 2.09 | 稳定 | 参照 |
| LoRA-GA | **13.95** | 4325 | 全选 A | 初始化就改变了函数 |
| LowRA | **9.08** | 3424 | 全选 A | 初始化就改变了函数（1.75 bit 量化） |
| PiSSA | 0.2774 | **32.3** | 第 6 步 loss 3.58 | 初始化基本保持，优化发散 |
| EVA | 0.2723 | **52.0** | 峰值 247,255 | 同上 |
| RandLoRA | 0.2723 | **22.6** | 峰值 8,285 | 同上 |
| Magnitude-LoRAM | 0.2807 | **24.7** | 开发分 40→66→24 | 同上 |
| LoRA+ | 0.2723 | 2.09 | 第 5 步 18.4 | `B` 的学习率是 3.2e-3，无预热 |

- 第二类的共同点是：初始 loss 正常，但第 1 步梯度范数是 LoRA 的 10–25 倍，随后几步内发散。这些方法的 `A`/`B` 初始尺度都比 Kaiming-LoRA 大（主奇异方向、激活主成分、随机满秩基），同样的 Adam 步长对应的函数变化大得多。这类方法通常需要各自调整学习率和预热（应对照各原论文的设置核实）。**在每个方法各自做过学习率搜索之前，这些分数不能进表。**
- LoRA-GA 的代码（`experiments/ms_swift_aqa/paper_early_ga.py` L15–28）把 `W − s·BA` 直接写回 BF16 权重（L28），再在前向里加回 FP32 的 `s·BA`。两个大项相消，结果对舍入非常敏感；具体机理见 §2.2，仍需测量。
- LowRA 把基座量化到 1.75 bit 后只训练 256 步，这个设定下没有恢复是预期内的，它与其他臂不在同一个问题上。

## 2. 有日志支持但尚未证实

### 2.1 问题表示在样本间几乎是常量

支持：门的样本相关变化只占其偏离的约 10%（§1.1e）；`e_prompt` 的构造（模板 token 主导的 embedding 均值，再经一个与 embedding 空间无关的投影）。
未证实：没有直接测过 `e_prompt` 或 `A·e_prompt` 在开发集上的两两余弦相似度。
验证办法：在服务器上对 256 条 AVQA dev 计算该相似度矩阵（不需要训练，几分钟）。

### 2.2 LoRA-GA 的初始化失真来自 BF16 下的大数相消

支持：更新前 loss 13.95 对 0.27；同样写回 BF16 残差的 PiSSA 只偏 0.005。两者的区别是：PiSSA 抵消的是 `W` 自身的主分量；LoRA-GA 抵消的是一个与 `W` 尺度无关的量（`stable` 缩放下奇异值约为 `2·(m^0.25/√γ)²`，2048 维输出时约 5.7），而且它的 `A` 取自梯度的右奇异方向，这些方向天然对齐隐状态里范数最大的方向。
未证实：没有在 FP32 与 BF16 下分别比较初始化前后的 logits。
验证办法与修法：对 1 个 batch 比较"干净基座 / 初始化后 FP32 / 初始化后 BF16"的 logits。若确认，把初始化改成保留原始 `W` 不动、前向用 `W x + s·(B A − B₀ A₀) x`（`B₀, A₀` 为冻结的初始副本）。这样初始时两项逐位相同，抵消是精确的，数学上与论文等价。

### 2.3 28 篇表的 MMAU 列主要反映"模型被改动了多少"

由 `scores.json` 与各臂 `result.json` 重算（只看没有崩溃的 17 个臂）：

- AVQA 开发准确率比冻结基座（71.1%）高出不到 2.5 pp 的 4 个臂（IGU-LoRA 71.5、Uni-LoRA 71.9、LoRAGen 73.0、LoRAM 73.4），MMAU 为 74.0–75.8，贴近冻结值 75.7；
- 开发准确率 ≥ 77% 的 13 个臂，MMAU 全部在 71.6–73.7。

也就是说，凡是学会了源任务的方法都在 MMAU 上掉 2–4 pp，没怎么学会的方法都"保住"了 MMAU。表中 LoRAM-TrainSmall、Uni-LoRA 的 MMAU 领先，更像是"改动小"而不是"方法好"。这与已发表的观察一致：在 Qwen2.5-Omni 上做 LoRA 微调后，MMAR 上升而 MMAU 明显下降（见 [`ACL_ASSESSMENT.md`](ACL_ASSESSMENT.md) §2 的文献）。
未证实：没有度量各臂对基座的实际改动量（例如与冻结基座预测的一致率）。逐题预测在服务器上，可以直接算。

### 2.4 "欠拟合 / 过拟合 / 迁移损失"的现状

- AVQA 源任务：普通 LoRA 在第 32 步就到 80.1%，之后在 79.3–80.5% 之间平台。源任务几乎立刻饱和。
- 合成配对任务：168 步时仍在上升，属于训练不足。
- 目标集：MMAU、MMAR 低于冻结基座，属于迁移损失；IEMOCAP 高于冻结基座。
- 训练 loss 每题监督约 3 个 token，其中结束符等占了大头，`token_acc` 不能当作答案准确率（交接文档 §8 已指出）。

所以"继续训练"对三件事的效果不同：对源任务没有空间，对合成配对有空间，对 MMAU 很可能更差。延长训练是否值得，取决于先把主评测改成能回答研究问题的集合。

## 3. 需要控制实验检验的假设

每个假设对应 [`experiments/cota_review/matrix.json`](../../experiments/cota_review/matrix.json) 里的一对臂，两臂之间只差一个因素。判定规则和预算在 [`PROTOCOL.md`](PROTOCOL.md) 中预先写定。

| 编号 | 假设 | 对照（只差一个因素） | 若假设成立应看到 | 若看到则否定 |
|---|---|---|---|---|
| H1 | 读出的是"音频/文本差"这件事有用，而不只是首答案位置多了一组参数 | `cota-static` vs `ctrl-ordinary` | 音频依赖开发集上 CoTA 更高，区间不含零 | 两者无差别 → 收益（若有）来自位置和参数 |
| H2 | 同预算下 CoTA(static) 不劣于并在音频依赖题上优于 LoRA | `cota-static` vs `lora-r12` | 同上 | 无差别或更差 |
| H3 | 减去文本均值是必要的 | `cota-static` vs `ctrl-audio-mean` | 差分更好 | 无差别 → 机制退化为"放大音频读出"，与已有工作重合 |
| H4 | 门在数值上生效后，条件化带来额外收益 | `cota-qa-live` vs `cota-static`；同一检查点 `--ablation neutral_gate` | 强制 m=1 后下降，且换音频时门的变化与答案是否该变相关 | 强制 m=1 无影响 → 放弃"条件"主张 |
| H5 | 独立读出 `C` 比共用 `B` 更好 | `shared-r12` vs `lora-r12`；检查点内 `no_shared` / `no_independent` | 需要 `C` 才有收益 | 共用 `B` 即可 → 方法可简化为 +12 参数/层 |
| H6（探索） | 只在答案位置改动模型，能减少对其他任务的负迁移 | `C` 单独训练 vs 普通 LoRA（需另加一个冻结普通分支的臂） | 目标集更接近冻结基座而源任务仍提升 | 无差别 |

H1 是最关键的一个：它决定 CoTA 有没有属于自己的机制。H4 决定名字里的 Conditional 能不能留。

## 4. 对你提出的检查清单的逐项结论

**实现正确性**
- 音频/文本划分、padding、因果 mask、答案位置、KV cache：静态检查未发现错误（§1.4）。
- 答案泄漏：没有（§1.4）。条件输入是否有效：数值上基本无效（§1.1）。
- 梯度：`C`、`A`、`B` 有效；`g` 和 `R` 初始梯度为零，之后量级很小，`R` 的更新与噪声无异（§1.1）。
- 初始化与缩放：零更新初始化成立，缩放匹配（§1.5）。BF16：门控系数被舍入（§1.1c），训练与推理数值路径不一致。
- 完整关闭传输：语义正确（§1.4）。
- 保存后从干净基座重载：`plugin.py` 的保存/恢复按版本严格校验；我没有执行，依据是原环境的测试记录。
- 支持范围：Omni、O-only、eager、非 packing、单 beam、单 token 答案；梯度检查点被拒绝。与交接文档一致。

**比较公平性**
- 基座、processor、提示、解码、文本处理在两臂间一致（配置逐项相同；`analysis/fairness.json`）。
- 参数预算接近、缩放相同；但 LoRA 的普通秩是 12，CoTA 是 8，缺 rank-8 对照（§1.5）。
- 学习率、训练量、选模规则相同，但规则本身噪声过大（§1.2）；单种子。
- 论文基线：见 §1.6，需按方法调参后才可比较。

**方法机制**
- 动态门是否随问题和音频变化：变化量在 1e-4 量级，九成是常数偏置（§1.1）。
- 收益来自哪里：目前没有稳定收益可供归因；现有对照无法区分 `C`、额外参数、注入位置（§1.5、§3）。
- 问题表示、归一化、共享低秩空间、单位置限制：问题表示是最弱的一环（§1.4、§2.1）；归一化使门只能看到方向看不到幅度；`A` 被三种不同统计的输入共用。
- 捷径：合成配对存在强时长捷径（§1.3）。

**训练与任务匹配**：见 §2.4。AVQA→情感是迁移协议，与监督训练 IEMOCAP 不是一回事；现有两套实验都没有用情感训练数据。
